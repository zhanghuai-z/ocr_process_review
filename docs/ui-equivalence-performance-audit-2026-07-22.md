# UI 等价恢复与性能审计（2026-07-22）

## 范围与证据

- 旧 UI 基线：`7134bfc^`（架构切换前最后一版成熟 proof UI）。
- 当前基线：`8e081a3` 加本次排序与性能改动。

- 压力模型：按真实页的不可变 `ProofWorkspaceView` 扩展为 10/30 页，仅用于 UI 规模测试。
- 环境：WSL、i5-8300H（4 核 8 线程）、7.7 GiB 内存、仓库位于挂载盘。绝对时间不能代替 Windows 交付机实测，冷热路径和相对差异有效。

## 等价恢复结论

按 24 项成熟用户能力核对：代码层已恢复全部 24 项，新增恢复项仍待 Windows 交互验收。旧版直接持有并修改 `Page/Line`、跨面板 bus、`merge_pages()` 和 stale-editor 补丁链不计为用户能力；它们已由不可变工作区、稳定 UID、CAS 编辑命令替代，不应找回。

## 当前数据边界

`ProjectSession` 是业务事实容器；`ProofWorkspaceView` 是完整只读视图，`ProofWorkspacePatch` 是从已提交仓储事实生成的增量投影。HProof/VProof 只维护焦点、选择、未提交文本等 UI 状态。编辑通过 `ProofEditCommand` 或 `ProofBatchEditCommand` 进入 `ProofSessionService`，成功后控制器按变更 UID 发布同一补丁。当前没有为性能引入第二文本事实源、兼容适配器或静默 fallback。

## 本次性能修复

1. 纵校缩略图从“每个字符重新解码一次整页 PNG”改为“每页解码一次后批量裁图”，并以页面 revision + bbox 缓存最多 512 个图标。bbox、原图和文字事实均未改变。
2. 横校不再创建每一行时同步渲染全部独立公式；仅当前公式行渲染。普通项目打开不再为不可见公式支付 MathJax 成本。
3. 公式 payload 在后台串行渲染，源码 hash 已过期的完成结果不会进入 GUI 物化。
4. Proof 提交只重建受影响文本单元的字符索引与行投影，横纵校合并同一增量视图。
5. 同目标保存复用未变资产；LayoutPanel 对相同工作区、OCR 框和当前页短路。

从真实项目等距抽取 20 个汉字/字母/数字/标点裁图，新旧裁图路径像素逐点一致（20/20）；性能优化没有改变纵校视觉证据。

## 后续优先级

P1/P2 代码项已完成。尚未完成的是在 Windows 交付机使用 1/30/100 页真实项目运行 `scripts/benchmark_release_workflow.py`，记录冷启动、P50/P95、峰值 RSS，并按下列目标验收；本报告仍不把 WSL 数值当发行 SLA。

## 建议响应目标

- 普通点击、同字切换、模块切换：P95 < 50 ms。
- 横校换行、纵校换字符桶：P95 < 100 ms。
- 单次文本提交到两个视图一致：P95 < 200 ms。
- 项目打开：30 页 < 3 s；显式保存：30 页 < 2 s（不变资产不重拷）。
- 公式预览可延迟完成，但主线程单次阻塞不得超过 50 ms。
