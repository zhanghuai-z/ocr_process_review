# UI 等价恢复与性能审计（2026-07-22）

## 范围与证据

- 旧 UI 基线：`7134bfc^`（架构切换前最后一版成熟 proof UI）。
- 当前基线：`8e081a3` 加本次排序与性能改动。
- 真实样例：`file/0722test/test1.ocrproj`，1 页、33 行、931 个纵校字符项、6.69 MiB。
- 压力模型：按真实页的不可变 `ProofWorkspaceView` 扩展为 10/30 页，仅用于 UI 规模测试。
- 环境：WSL、i5-8300H（4 核 8 线程）、7.7 GiB 内存、仓库位于挂载盘。绝对时间不能代替 Windows 交付机实测，冷热路径和相对差异有效。

## 等价恢复结论

按 24 项成熟用户能力核对：22 项等价恢复，1 项部分恢复，1 项未恢复。旧版直接持有并修改 `Page/Line`、跨面板 bus、`merge_pages()` 和 stale-editor 补丁链不计为用户能力；它们已由不可变工作区、稳定 UID、CAS 编辑命令替代，不应找回。

### 已等价恢复（22 项）

横校已具备页面目录、当前/相邻/远端行层级、原稿与文本槽对齐、字符选择与 IME 编辑、保存/确认/标记/跳过、撤销重做、冲突保留、公式/表格调试过滤、表格大图模式、进度统计、行内公式气泡、独立公式三栏、公式序号软链接。

纵校已具备全项目字符索引、搜索、多字符桶选择、相同字索引、原稿整页定位、整页 OCR 文本上下文、反向点图定位、直接输入/置空、右键气泡、候选字、批量修改、撤销重做、工作区刷新后的稳定选择恢复。

### 部分或未恢复

| 能力 | 状态 | 价值判断 |
|---|---|---|
| 纵校高级扩选快捷键（旧版 `Shift+Alt+方向`、`Ctrl+Alt+方向`） | 部分；基础方向导航、整组选中仍在 | 中。高频键盘校对用户有价值，但不阻塞发行 |
| 横校左侧目录折叠 | 未恢复 | 中高。窄屏和长公式场景可明显扩大画布，建议恢复为纯 UI 状态 |

旧版 quality-probe 假字注入、panel bus、按可变页面对象合并、兼容字段诊断没有恢复。这些属于实验/旧架构机制，不应重新进入当前 UI；若重新启用质量抽检，应作为独立业务能力重新设计。

## 当前数据边界

`ProjectSession` 是业务事实容器；`ProofWorkspaceView` 是一次性只读视图；HProof/VProof 只维护焦点、选择、未提交文本等 UI 状态。编辑通过 `ProofEditCommand` 或 `ProofBatchEditCommand` 进入 `ProofSessionService`，成功后控制器重新发布工作区。当前没有为性能引入第二文本事实源、兼容适配器或静默 fallback。

## 本次性能修复

1. 纵校缩略图从“每个字符重新解码一次整页 PNG”改为“每页解码一次后批量裁图”，并以页面 revision + bbox 缓存最多 512 个图标。bbox、原图和文字事实均未改变。
2. 横校不再创建每一行时同步渲染全部独立公式；仅当前公式行渲染。普通项目打开不再为不可见公式支付 MathJax 成本。

从真实项目等距抽取 20 个汉字/字母/数字/标点裁图，新旧裁图路径像素逐点一致（20/20）；性能优化没有改变纵校视觉证据。

## 后续优先级

### P1

1. 公式渲染改为异步预览：源码编辑和换行绝不能被 Node/MathJax 阻塞；结果按源码 hash 回到 GUI 线程，旧结果丢弃。
2. Proof 工作区支持按受影响 `proof_uid/text_unit_uid` 增量发布。当前每个字符修改仍重建完整 proof 视图并同时刷新 H/V 两个面板。
3. 保存拆分 DB 原子提交与不变资产复用。当前每次保存都重新 stage 全部资产，页数增长后不可接受。

### P2

1. 项目打开时合并 LayoutPanel 的 layout、OCR overlay、current-page 四次刷新，避免重复创建约 1,900 个图元。
2. 恢复横校目录折叠和纵校高级扩选快捷键；只改 UI 状态，不触碰业务模型。
3. 在 Windows 交付机增加 1/30/100 页基准，记录冷启动、P50/P95、峰值 RSS；本报告不把 WSL 数值当发行 SLA。

## 建议响应目标

- 普通点击、同字切换、模块切换：P95 < 50 ms。
- 横校换行、纵校换字符桶：P95 < 100 ms。
- 单次文本提交到两个视图一致：P95 < 200 ms。
- 项目打开：30 页 < 3 s；显式保存：30 页 < 2 s（不变资产不重拷）。
- 公式预览可延迟完成，但主线程单次阻塞不得超过 50 ms。
