# OCR 后处理项目工程化升级规划

## 目标

当前项目已经具备 PySide6 桌面壳、PaddleOCR/API 调用、版面分析、项目存储、横校/纵校、TXT/XML/HTML/PDF/DOCX/RTF 导出等雏形，但主工作流还没有顺畅闭环，人工介入能力和 UI 操作逻辑仍偏原型。升级目标是按“重构级”标准，把项目改造成可持续扩展的 OCR 后处理工作台：先保证导入、版面、人工修框、OCR、校对、导出完整走通，再补齐更人性化的交互、美观 UI、人工画框与自动收紧能力，并建立清晰的数据模型、测试和打包体系。

## 当前代码审计结论

### 已有基础

- 技术栈清晰：PySide6 + SQLite 项目文件 + PaddleOCR/AiStudio API + OpenCV/Pillow/PyMuPDF 等。
- 领域模型已有基本抽象：`OcrProject`、`Page`、`Block`、`Line`、`Char`、`BBox`、`ProofStatus`。
- UI 已按步骤拆分：导入、版面分析、OCR、横校、纵校、导出。
- 基础测试覆盖模型、项目存储、ProofEngine、TXT/XML/HTML 导出；直接运行 `python tests/test_core.py` 可通过。
- 图像查看器已有缩放、平移和 BBox 叠加显示基础，适合继续扩展为可编辑画框画布。

### 关键问题

- 工作流状态不可靠：启动时步骤按钮默认可跳转；OCR 完成后的“进入校对”按钮会再次触发完成逻辑但不真正跳转到校对页；导出只检查有页面，不检查 OCR/校对状态。
- PDF 支持未走通：导入面板允许 PDF，但后续按图片路径处理，`PIL`/`cv2` 不能直接处理 PDF；`PyMuPDF` 依赖目前没有真正接入导入转换。
- 版面结果不可人工编辑：只能显示自动检测框，不能新增、拖拽、缩放、删除、合并、拆分、重排，也没有“粗画框自动收紧”。
- 存储全量保存有脏数据风险：重新版面分析时会追加新 block，旧 block/line 可能仍留在 SQLite 中，后续打开项目会读到过期结果。
- 配置和依赖不完整：代码使用 `requests`，但 `pyproject.toml` 未声明；OCR 配置是内存单例，关闭程序后不持久；源码中存在默认 API 地址，需改为显式用户配置。
- 错误处理和用户反馈偏弱：很多失败路径只是返回空结果或弹出笼统错误，缺少按页面/块定位、重试、跳过、取消、日志与恢复机制。
- 横校/纵校能力只是雏形：缺少疑点优先队列、键盘快捷键、自动保存策略、修改对比、进度闭环、整页/整块联动和低置信字符高亮数据来源。
- UI 视觉较基础：主要是深色样式叠加，缺少统一设计 token、工具栏、空状态、进度状态、图层颜色规范、缩略图导航和可发现的操作提示。
- 工程化不足：没有 README/架构说明；测试未覆盖 UI、状态机、PDF 导入、OCR 适配器、BBox 自动收紧、SQLite 迁移；构建脚本依赖手动安装并和 `pyproject` 不完全一致。

## 产品与操作逻辑建议

参考汉王类 OCR 软件的思路，推荐把产品主线设计为“批处理 + 人工校准 + 疑点优先校对”的工作台，而不是单纯的步骤演示页：

1. 导入建档：用户拖入图片/PDF，程序自动生成项目，建立页面队列、缩略图、预处理结果和可恢复的项目文件。
2. 自动预处理：自动处理 PDF 转图、方向检测、去黑边/纠偏、灰度增强、分辨率检查；所有处理结果可回看和重跑。
3. 版面识别与人工分区：自动分析版面后，用户可以粗画文字区/标题/表格/图片区，程序自动收紧到真实内容边界。
4. 区域级 OCR：允许整页 OCR、选区 OCR、失败重试、跳过非文字区、替换某个区域的识别结果。
5. 疑点优先校对：先把低置信、空识别、异常字符、疑似断行/串列的内容推到“疑点队列”，再允许按页顺序通校。
6. 横校/纵校合一：横校适合逐行快速修字，纵校适合整块/竖排/古籍式内容对照；两者共享同一数据和快捷键。
7. 导出归档：导出前显示完成度、未校对数量、疑点数量，支持只导出文本、保留版面坐标、生成校对报告。

## 总体重构方案

### 1. 工程基础与依赖治理

- 补齐 `pyproject.toml` 依赖：`requests`、打包所需依赖、可选本地 OCR/开发依赖分组。
- 建立 README：说明项目定位、安装、运行、OCR 模式、项目文件、构建方式。
- 明确源码目录和生成目录边界：`build/`、`dist/`、大样本文件不作为源码分析对象；若后续进入 git，应加入 `.gitignore`。
- 建立统一日志模块：GUI 弹窗显示人话，日志保存技术细节，避免失败时只看到“处理失败”。
- 引入配置持久化：用 `QSettings` 或项目级 settings 表保存 OCR 模式、API 地址、超时、界面偏好；Token 不写死在源码，优先使用安全存储或本机配置。

### 2. 工作流状态机与项目控制器

- 新增 `ProjectController` / `WorkflowController`，从 `MainWindow` 中抽离项目创建、打开、保存、步骤跳转、worker 调度。
- 为 `Page`、`Block`、`Line` 增加清晰状态：已导入、已预处理、已版面分析、已人工确认、已识别、已校对、导出候选等。
- 步骤按钮根据状态启用，禁止无效跳转；每个步骤提供明确的下一步动作和返回修改动作。
- OCR 完成后真正进入校对页，避免“进入校对”重复触发 `_on_ocr_done`。
- 支持取消、跳过当前页、重试失败页，并在状态栏/任务面板显示可恢复的进度。

### 3. 导入与图像预处理

- 接入 PyMuPDF，把 PDF 每页渲染为项目缓存目录中的图片，并记录 DPI、页码、源文件路径。
- 统一导入服务：校验文件类型、去重、排序、批量导入文件夹，显示导入失败原因。
- 建立项目缓存目录：保存 PDF 转图、预处理图、缩略图、OCR crop，避免重复计算。
- 加入基础预处理：方向检测/旋转、去黑边、灰度增强、二值化预览、分辨率提示。
- 每页保留原图和处理图映射，确保 BBox 坐标可追踪。

### 4. 数据模型、存储与迁移

- 为 SQLite 添加 schema version 和迁移机制，避免后续模型升级破坏旧项目。
- 保存项目时对页面、块、行、字符采用事务化 upsert，并删除已移除的旧子记录，解决重新分析后脏 block/line 残留。
- `Block` 增加来源字段：自动版面、人工画框、自动收紧、用户编辑；增加锁定、可识别、备注、阅读顺序等元数据。
- `BBox` 增加规范化工具：裁剪到图像边界、最小尺寸、面积、交并比、扩边、坐标变换。
- 保存用户操作历史，为撤销/重做、审计和校对报告打基础。

### 5. 可编辑版面画布与人工画框

- 将 `ImageViewer` 升级为可编辑画布，支持模式切换：浏览、选择、画框、移动、缩放、删除、拆分、合并、设置类型。
- 提供图层管理：自动块、人工块、OCR 行框、低置信高亮、当前选中框分别使用统一颜色和透明度。
- 支持框列表与画布双向联动：点击列表定位图上框，点击框显示属性，支持按阅读顺序上移/下移。
- 增加快捷键：删除框、复制框类型、确认当前页、跳到下一页、撤销/重做。
- 对人工粗画框提供“画完即收紧”和“手动收紧当前/全部”两种入口。

### 6. 粗画框自动收紧算法

核心目标是允许用户只画大概范围，程序自动把框缩到真实文字/图形内容边缘，而不是要求人工精准画框。

建议实现为独立服务 `BBoxTightener`：

- 输入：原图或预处理图、用户粗框、块类型、可选参数。
- 预处理：裁剪 ROI，转灰度，去噪，Otsu/自适应阈值，必要时反色，形态学闭运算连接文字笔画。
- 内容定位：用连通域、水平/垂直投影或轮廓寻找有效墨迹区域；过滤过小噪点和边框线。
- 收紧策略：取有效内容外接矩形，按块类型增加安全边距；文本区少量扩边，表格/图片区保留更多边距。
- 失败保护：若有效内容过少或收紧后面积异常，则保留原框并提示用户，而不是静默改变。
- 高级扩展：结合 OCR 检测框二次收紧；支持多列文本时按投影辅助拆块；支持“包含标点/页码/脚注”的边界策略。
- 测试要求：用合成图片覆盖噪点、空白、倾斜、竖排、多行、表格线、图文混排等场景。

### 7. OCR 管线重构

- 定义统一 `OcrEngine` 接口，拆分本地 PaddleOCR、AiStudio API、自部署 API 适配器。
- 版面分析和文字识别分离：允许只跑版面、只跑某个块 OCR、重跑失败块。
- 加入任务队列：按页/块汇报进度，支持取消、暂停、重试、失败列表。
- 对 OCR 输入做标准化：裁剪、扩边、方向、竖排参数、图像增强，保证人工框和自动框都能稳定识别。
- OCR 结果回写时保留原始引擎输出、置信度、检测框和字符级信息；没有字符级置信度时明确标记“不可用”。
- 对 API 响应增加结构校验和友好错误映射，避免 API 返回格式变化时只显示 Python 异常。

### 8. 校对工作台升级

- 建立统一校对数据源：横校、纵校、树状结果、导出都读取同一状态，不重复触发 OCR 完成逻辑。
- 疑点队列：低置信、空文本、异常字符、过短/过长行、疑似断行、重叠框、OCR 失败块优先呈现。
- 横校优化：左侧显示当前行及上下文，右侧文本编辑，支持 Enter/快捷键确认并自动下一行。
- 纵校优化：按块显示图文对照，支持整块编辑、合并/拆分行、保持阅读顺序。
- 修改对比：显示原始识别文本、当前文本、修改状态、确认状态；支持撤销当前修改。
- 完成度面板：展示总行数、已确认、已修改、疑点剩余、未识别块，导出前强提醒。

### 9. UI 美观与人性化操作

- 重新设计主窗口为“顶部工具栏 + 左侧页面缩略图 + 中央画布 + 右侧属性/任务面板 + 底部状态栏”。
- 统一视觉规范：颜色 token、间距、字体、图标、按钮层级、低置信/已确认/已修改状态颜色。
- 加入空状态和引导：首次打开提示“拖入文件开始”，版面页提示“自动分析或手动画框”，OCR 页提示“先确认识别区域”。
- 加入任务中心：显示当前批处理进度、失败页、可重试操作。
- 图像交互更贴近专业软件：滚轮缩放、空格/中键平移、框选工具、吸附/辅助线、适合窗口、100% 缩放。
- 提供设置面板：主题、快捷键、OCR 引擎、默认导出格式、自动保存间隔。

### 10. 导出、打包与交付

- 导出前校验工作流状态，提示未 OCR/未校对/疑点未处理项。
- 导出选项可配置：是否按页、按块、保留坐标、保留置信度、导出校对报告。
- HTML/XML 保留版面坐标；DOCX/PDF 支持更合理的段落和页分隔；TXT 提供纯净模式和带页码模式。
- 构建脚本以 `pyproject` 为依赖来源，减少脚本与项目配置不一致。
- 明确本地 OCR 大模型依赖和 API 模式的安装差异，避免普通用户首次安装过重。

### 11. 测试与质量保障

- 单元测试：BBox 工具、自动收紧、项目存储迁移、PDF 转图、导出器、ProofEngine。
- 集成测试：导入图片/PDF → 版面 mock → 人工框 mock → OCR mock → 校对 → 导出。
- UI 测试：步骤按钮状态、导入面板、版面画框、OCR 完成跳转、校对保存。
- OCR/API 测试使用 fake adapter，不依赖真实 PaddleOCR 或外网。
- 建立基础 CI 命令：安装轻量依赖、运行核心测试；本地 OCR 作为可选慢测试。

## 推荐实施顺序

第一阶段验收口径已确认：优先保证“导入 → 版面分析/人工确认 → OCR → 校对 → 导出 → 保存/再打开”完整闭环稳定走通，再推进人工画框增强、自动收紧、UI 美化和高级导出。

## 需要确认的假设

- 第一阶段优先目标已确认：先让完整工作流稳定走通，再做大规模视觉美化。
- 人工画框默认面向文字块，但也应支持标题、表格、图片、参考文献等块类型。
- 自动收紧应偏保守，宁可多留少量边距，也不要裁掉文字。
- 本地 PaddleOCR 和云端 API 都保留，但默认体验应允许用户在不安装大模型时使用 API/mock 快速跑通流程。
- 汉王式逻辑应借鉴“批处理、分区、疑点优先、键盘高效校对”的产品方法，而不是复制具体 UI。

## 补充技术假设

- LLM 文本流能力只做 OCR 结果的“预审/建议层”，人工校对仍是终审，不允许 LLM 直接覆盖最终文本。
- LLM 预审必须可关闭，默认建议第一阶段关闭；开启后仍要保留原始 OCR 文本、LLM 建议文本、人工最终文本三份数据。
- LLM 预审入口应位于 OCR 结果写入之后、人工校对之前；导出必须只读取人工最终文本，除非用户明确接受 LLM 建议。
- LLM 预审应支持 fake/mock adapter，测试和基础工作流不得依赖外网、真实模型或 API key。
- LLM 预审只发送文本和必要上下文，不发送原图、Token、项目文件路径等敏感数据；后续如需图像多模态能力，必须单独加开关和用户确认。
- LLM 预审失败不能阻断 OCR 主流程，应记录为“预审失败/未启用”，并允许用户继续人工校对。
